# stage4 — Web／App 账号闭环

[返回总索引](../README.md)

- 状态：未开始。
- 前置依赖：stage3。
- 目标：将两端禁用的账号预览替换为真实注册、登录和会话恢复体验。

## 任务清单

- [ ] Vue 接入登录、注册、验证提示、找回/重置、退出和当前用户状态。
- [ ] Flutter 接入相同账号业务，区分模拟器、实机与生产地址配置。
- [ ] Web 使用已确定的 Cookie 流程，不把长期凭证放进 localStorage。
- [ ] App 将敏感凭证存入系统安全存储，处理刷新轮换及并发刷新。
- [ ] 实现路由权限、启动恢复、凭证失效、网络失败、提交中与重复点击处理。
- [ ] 保留安全的站内登录后返回目标，为邀请链接准备入口；拒绝任意外部跳转。
- [ ] 明确同账号跨设备登录与单局操作连接的区别，后者在 stage12 完善。

## 交付与范围

修改 web/src 的账号/会话模块、flutter/lib/features/auth 和网络配置；同步两端错误文案与协议类型。此阶段只开放已真实实现的账号能力。

## 验收标准

- [ ] 同一个账号可以分别在 Web/App 登录，稳定对应同一 userId。
- [ ] 刷新网页、重启 App、凭证过期和退出登录均符合约定。
- [ ] 错误密码、服务不可达、邮件未验证等状态有清晰提示，不模拟成功。
- [ ] 登录失败不进入受保护页面，退出后不能继续使用已撤销会话。
- [ ] 两端注册到退出的流程有自动测试；移动端安全存储验证记录可追溯。

## 本阶段不包含

创建真实房间、对局和完整个人战绩。跨端登录不代表对局已经互通。

## 完成记录

待补两端流程测试、验证设备/浏览器、会话恢复结果和功能开关变化。
