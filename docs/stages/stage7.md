# stage7 — 实时对局后端

[返回总索引](../README.md)

- 状态：部分完成（经典房间启动、HTTP/WebSocket 动作、权威状态持久化与私有推送已实现；计时和多人整局验收未完成）。
- 前置依赖：stage3、stage5、stage6。
- 目标：把真实身份、房间和规则引擎连成服务器权威的实时对局。

## 任务清单

- [x] 实现标准 WebSocket 连接、握手/逐消息/定期会话核验和消息格式校验；网关路由指向真实 handler。
- [x] 房主在全员准备且版本匹配时，原子创建经典对局、保存发牌状态并切换房间；重复启动返回现有对局。
- [x] 按对局成员读取持久化状态并由规则引擎生成个人视图，非成员无法查看。
- [x] HTTP 动作按对局行锁串行执行，校验协议版本、对局版本及规则；同一身份/对局/commandId 重试不重复执行。
- [x] 落地 protocolVersion、commandId、matchId、expectedVersion 和 WebSocket 确认/拒绝事件。
- [x] 同一对局按序处理动作，校验席位、卡牌归属、轮次与规则，拒绝客户端自报胜负。
- [x] 实现命令去重、状态版本、初次/重新连接的完整状态同步，不盲信传输层重连。
- [x] 按接收者生成私有视图；禁止广播完整手牌后交给客户端隐藏。
- [ ] 接入基本回合/质疑计时，权威截止时间由服务器决定；完整断线策略在 stage12 验收。
- [ ] 建立正常结束/系统中断的最小对局记录，保证结算幂等，为历史查询留可靠来源。
- [ ] 限制消息体大小、发送速率和非法动作；日志不包含凭证或全部手牌。

## 交付与范围

修改 game-service、gateway、对局迁移与协议文档，调用 game-core 而不重写规则。此阶段必须有可实际连接的测试客户端，不仅是事件名称清单。

## 验收标准

- [ ] 多个真实账号的测试连接可完成一局，赢家由服务器判定。
- [ ] 同一个 commandId 重试不会多摸牌、多出牌或重复结算。
- [ ] 乱序/过期版本被明确处理；两条竞争动作不能同时推进同一轮。
- [ ] 旁观或伪造账号不能操作席位；网络报文不暴露非授权手牌。
- [ ] 初次连接/重连返回与当前身份一致的完整视图，撤销会话后连接停止业务操作。

## 本阶段不包含

两端完整交互、机器人、多实例房间迁移、文字业务和真实语音。
