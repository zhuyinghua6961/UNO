# stage5 — 房间与组队准备

[返回总索引](../README.md)

- 状态：部分完成（后端与两端代码、跨服务 HTTP 联调已通过；真机与界面联调待验收）。
- 前置依赖：stage4；2v2 暂按四位真人、两队各两人实现，仍待产品确认。
- 目标：真实玩家能够创建、邀请、加入、准备和离开同一个等待房间。

## 任务清单

- [x] 建立房间、席位、成员、模式、准备状态和版本，保证服务器唯一裁决。
- [x] 实现创建、随机房间码、Web 邀请链接、加入、查看与离开；加入限流、同账号重复加入不占座。
- [x] 定义人数上限、房满、邀请码 24 小时失效、非等待状态拒绝加入；同账号只占一个席位，版本阻止过期操作。
- [x] 实现房主移交、空房回收、规则变更重置准备状态。
- [x] 实现 2v2 等待阶段分队：两队各两人、交替座位、全员准备后标记 canStart。
- [x] 两端接入真实大厅与等待页；Web 登录返回邀请链接，App 登录前输入房间码后自动加入。
- [x] 预留 WAITING/STARTING/PLAYING 状态；stage7 前没有启动对局端点或可点击的启动按钮。

## 交付与范围

主要修改 backend/game-service 的房间模块、两端大厅/房间、房间迁移与协议。初期可以使用受控查询刷新验证等待状态，实时快照通道在 stage7 统一接入。

## 验收标准

- [ ] 不同真实账号在 Web 与 App 界面看到一致成员、模式、队伍和准备状态：跨服务 HTTP 已验证，界面与真机待验收。
- [x] 并发争抢最后一个位置不超员；重试加入不重复占座。
- [x] 非房主不能改房间规则，非成员不能读取私有房间或准备状态。
- [x] 2v2 未凑齐 2+2 或未全员准备时 canStart 为 false；非 WAITING 状态禁止换队。
- [ ] 房主离开、邀请码失效、空房回收已验证；Web 登录返回邀请路径有路径测试，完整界面链路与 App 登录后加入仍待设备验收。

## 本阶段不包含

真实发牌、UNO 规则、文字传输、语音和随机匹配。可组局不等于可打牌。
