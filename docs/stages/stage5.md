# stage5 — 房间与组队准备

[返回总索引](../README.md)

- 状态：未开始。
- 前置依赖：stage4；已确认 2v2 含义。
- 目标：真实玩家能够创建、邀请、加入、准备和离开同一个等待房间。

## 任务清单

- [ ] 建立房间、席位、成员、模式、准备状态和版本，保证服务器唯一裁决。
- [ ] 实现创建、邀请链接/随机房间码、加入、查看与离开，限制暴力尝试和重复加入。
- [ ] 确认人数上限、房满、邀请码失效、已开局和重复设备的处理。
- [ ] 实现房主移交、空房回收、规则变更重置准备状态。
- [ ] 实现 2v2 等待阶段分队：两队各两人、交替座位、全员准备后允许开局。
- [ ] 两端接入真实大厅与等待页，登录后能回到受邀房间。
- [ ] 预留明确的启动对局交接状态；stage7 完成前不把等待页按钮伪装成可开局。

## 交付与范围

主要修改 backend/game-service 的房间模块、两端大厅/房间、房间迁移与协议。初期可以使用受控查询刷新验证等待状态，实时快照通道在 stage7 统一接入。

## 验收标准

- [ ] 不同真实账号能在 Web/App 看到一致成员、模式、队伍和准备状态。
- [ ] 并发争抢最后一个位置不超员；重试加入不重复占座。
- [ ] 非房主不能改房间规则，非成员不能读取私有房间或准备状态。
- [ ] 2v2 未凑齐 2+2 或未全员准备时无法启动；开局后禁止换队的约束已定义。
- [ ] 房主离开、邀请码失效、空房回收和登录返回邀请都有验证。

## 本阶段不包含

真实发牌、UNO 规则、文字传输、语音和随机匹配。可组局不等于可打牌。

## 完成记录

待补房间状态定义、并发加入测试、两端邀请链路和权限验证。
