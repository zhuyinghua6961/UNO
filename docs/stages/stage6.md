# stage6 — 经典 UNO 规则引擎

[返回总索引](../README.md)

- 状态：未开始。
- 前置依赖：stage1；不依赖账号 UI，可独立开发和测试。
- 目标：在 game-core 内实现与网络、数据库和动画无关的经典规则。

## 任务清单

- [ ] 定义逻辑牌 ID、牌型、颜色、牌堆、手牌、方向、行动玩家和阶段状态。
- [ ] 创建基础牌组与洗牌/发牌；生产随机源与测试固定种子通过可控输入区分。
- [ ] 实现合法出牌、摸牌、摸牌后出牌/放弃，拒绝非法或越回合动作。
- [ ] 实现跳过、反转、+2、万能选色和 +4 质疑，保留质疑所需的出牌时证据。
- [ ] 实现 UNO 宣告与抓漏喊窗口、初始功能牌、末张功能牌、两人局等规则分支。
- [ ] 实现弃牌堆重洗、胜负判定和完整牌数守恒，不依赖 UI 动画驱动状态。
- [ ] 定义明确的动作结果、错误原因、规则版本与玩家私有视图。
- [ ] 根据已确认规则补表驱动测试与边界测试，默认不混入叠加/抢出等家规。

## 交付与范围

修改 backend/game-core，输出规则说明与测试用例清单；不把网络登录或数据库连接引入纯规则模块。已有 CommunicationPolicy 测试不是 UNO 规则测试。

## 验收标准

- [ ] 相同初始状态、随机输入和动作序列得到相同结果。
- [ ] 合法/非法动作、两人局、功能牌收尾、UNO 窗口、+4 质疑均有明确用例。
- [ ] 对局过程中牌不重复、不丢失，总量守恒；规则拒绝不会部分修改状态。
- [ ] 私有视图只能看到本人手牌，其他玩家仅公开信息；质疑证据按规则定向处理。
- [ ] 测试覆盖一次正常完整对局以及至少一条关键罚牌链路。

## 本阶段不包含

WebSocket、计时调度、真人界面、2v2 胜负、机器人与排行榜。

## 完成记录

待补规则决策版本、测试矩阵、边界用例和实际验证结果。
