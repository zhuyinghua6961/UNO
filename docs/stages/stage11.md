# stage11 — 房间／队伍文字聊天

[返回总索引](../README.md)

- 状态：进行中（房间与队伍文字已在 Web 分别搭配 Android、iOS 模拟器互发并完成 2v2；消息推送事件与内容处理未完成）。
- 前置依赖：stage5、stage7、stage10。
- 目标：两端真实发送/接收房间与队伍文字，队伍内容不向无权用户泄露。

## 任务清单

- [ ] 实现 CHAT_SEND 与消息事件，服务器生成身份、消息 ID、时间和频道序号。
- [x] 使用服务器成员/队伍关系计算接收者，不接受客户端指定 senderId 或收件人列表。
- [x] 房间文字对房间成员可见；队伍文字仅同队可见，经典模式无队伍频道。
- [x] 接入内容长度、控制字符、纯文本展示、服务器限流和幂等发送（房间文字）。
- [ ] 确定历史保存时长、退出/换队后的查询范围、删除和举报需求，再实现对应迁移与历史接口。
- [x] 实现游标补消息、去重和权限检查；旧队伍消息不得通过历史查询绕过隔离。
- [x] 两端接入发送中、失败/重试、未读提示与频道切换，网络失败不伪装已送达。
- [ ] 定义基础禁言/禁用账号联动和用户内容处理入口，公开试用前不能完全缺少处理途径。

## 交付与范围

影响 game-service、消息迁移、两端通信 UI 和协议。聊天序号独立于游戏状态版本；聊天失败不应卡住出牌。已有消息格式/受众单元测试不能替代真实通道授权测试。

## 验收标准

- [ ] Web 与 App 可互发消息，消息身份和时间不能由客户端冒充。
- [ ] A 队实时消息和历史均不可被 B 队、非成员或已退出用户越权读取。
- [ ] 重试消息不重复落库/展示；断线补历史不丢失允许查看的消息。
- [ ] 富文本攻击作为普通文字展示；超长、刷屏、禁言身份按约定拒绝。
- [ ] 真实保存/删除策略可验证，测试日志不随意保存完整聊天内容。

## 本阶段不包含

图片、附件、自由私信、语音消息、机器人内容审核平台；队友音频在 stage13–stage15 实现。
