# stage3 — 后端账号与会话

[返回总索引](../README.md)

- 状态：未开始。
- 前置依赖：stage2；正式实现前确认登录渠道。
- 目标：提供真实身份体系，为房间、聊天与语音提供可信 userId。

## 任务清单

- [ ] 按已确认渠道实现注册；当前建议邮箱＋密码，并区分展示昵称和固定身份。
- [ ] 使用成熟密码哈希实现，处理重复注册、无效输入和不泄露账号存在性的错误反馈。
- [ ] 实现登录、当前用户、退出；明确 Web Cookie 和 App 短期/刷新凭证的有效期、轮换与撤销。
- [ ] 接入邮箱验证、找回密码和一次性过期令牌；本地邮件测试工具不能当作真实邮件投递。
- [ ] 处理刷新重放、退出后凭证失效、密码重置后的旧会话策略。
- [ ] 实现登录/注册/找回限流、基础账号禁用能力、日志脱敏。
- [ ] 明确网关与业务服务的可信身份传递/校验，拒绝伪造 userId 或认证请求头。
- [ ] 更新协议文档与真实功能状态，不一次性开放全部未完成端点。

## 交付与范围

主要修改 backend/identity-service、gateway、数据库迁移和 docs/contracts。Web Cookie 的 CSRF/Origin 等保护与认证一起交付，不能等到最后阶段再补。

## 验收标准

- [ ] 两个真实账号能独立注册登录，数据互不混淆；数据库没有明文密码或原始重置令牌。
- [ ] 正确/错误/过期/撤销凭证与重复邮箱均有测试。
- [ ] 找回凭证只能使用一次，重置后旧凭证按约定失效。
- [ ] 不能绕过网关或伪造头部冒充用户；被禁用身份不能新建有效会话。
- [ ] 不借助硬编码演示账号或 permitAll 通过端到端检查。

## 本阶段不包含

双端完整账号 UI、房间、好友系统和多种第三方登录。未确认的手机号/微信登录不擅自加入范围。
