# stage2 — 数据库与迁移基础

[返回总索引](../README.md)

- 状态：已完成（本地开发范围，2026-09-06）。
- 前置依赖：stage1；产品规则/分支仍未定，本阶段按工程基线记录的依赖例外推进，不代表 stage1 全部完成。
- 目标：让后端能安全访问真实数据库，并以可重复迁移而非手工改表管理结构。

## 任务清单

- [x] 明确持久化方案和连接配置，接入 PostgreSQL；Redis 仅在会话/限流实际需要时接入。
- [x] 建立数据库迁移目录和版本规范，不通过 ORM 自动改生产表。
- [x] 创建账号、会话、账号验证/重置令牌所需基础表与唯一约束。
- [x] 定义房间/对局/队伍/消息/结果的数据关系草案；各功能阶段再提交自身迁移，不预建全部未来业务表。
- [x] 定义事务、唯一性冲突、时间存储、分页以及数据库不可用时的错误行为。
- [x] 区分开发、测试、生产配置；密钥来自环境或受控秘密管理。
- [x] 建立隔离的数据库集成测试和最小备份恢复操作步骤。

## 交付与范围

影响 backend/identity-service、backend/game-service、deploy、docs。输出迁移规范、已执行迁移与数据访问测试。启用数据库容器不等于服务已使用数据库。

## 验收标准

- [x] 空数据库可迁移至当前版本；重复运行不破坏数据。
- [x] 从上一版本升级保留测试数据；迁移失败不会留下伪成功状态。
- [x] 账号关键字段唯一性、令牌过期字段和事务回滚有数据库级测试。
- [x] 服务重启后已提交数据仍存在，连接故障不泄露密码或内部堆栈。
- [x] 测试与开发/生产数据隔离，不在共享数据库执行破坏性测试。

## 本阶段不包含

登录业务、完整房间功能、消息发送和缓存扩容。数据库结构不代表对应功能可用。
