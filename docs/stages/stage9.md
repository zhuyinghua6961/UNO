# stage9 — Flutter 经典对局

[返回总索引](../README.md)

- 状态：未开始。
- 前置依赖：stage7；与 stage8 共用同一后端协议。
- 目标：让 App 加入真实牌桌，并与 Web 互通完成经典局。

## 任务清单

- [ ] 实现网络地址与环境配置、实时连接、凭证失效和状态订阅生命周期。
- [ ] 接入真实房间、牌桌、选牌/出牌/摸牌/放弃/选色、UNO 与 +4 交互。
- [ ] 支持手牌滑动、清晰点击区域、服务器回合时间与动作等待反馈。
- [ ] 实现结算、返回房间和再来一局，清理页面重建产生的旧订阅。
- [ ] 定义 App 前后台、系统返回、网络切换的基本表现；完整恢复在 stage12 统一验收。
- [ ] 为 Android/iOS 准备调试运行与网络权限配置，不为解决本地问题放宽生产安全策略。
- [ ] 接入卡牌素材及音效偏好，保留第三方素材说明。

## 交付与范围

修改 flutter 的网络、房间、对局与结算模块，复用服务器规则和 JSON 协议。确认 Android/iOS 目标；缺少某平台工具链只能记录未验收，不能视作跨平台已完成。

## 验收标准

- [ ] 至少一个 Web 账号与一个 App 账号同桌完成对局，双方状态一致。
- [ ] UNO、+4、选色和功能牌可通过触控操作，不依赖开发调试入口。
- [ ] 目标 Android/iOS 运行环境记录明确；静态分析、widget 与集成流程测试通过。
- [ ] 进入/离开牌桌和重复打开页面不增加重复监听、不重复发指令。
- [ ] 平台未验证项被明确列为待办，不以 Flutter 编译能力代替实测。

## 本阶段不包含

App 商店发布、正式分发签名、后台语音、2v2 和文字通信。

## 完成记录

待补设备/模拟器清单、Web/App 混合对局结果、平台差异与测试报告。
