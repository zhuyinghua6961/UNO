# stage16 — 个人中心与对局记录

[返回总索引](../README.md)

- 状态：未开始。
- 前置依赖：stage10、stage12；不需要等待语音开发完成。
- 目标：用真实记录替换个人中心占位，让账号能够保存偏好与对局历史。

## 任务清单

- [ ] 实现昵称、预置头像和音量等偏好更新；敏感账号修改仍走身份模块校验。
- [ ] 从幂等结算记录提供近期对局、正常完赛、个人结果和团队结果。
- [ ] 区分经典个人胜利、2v2 团队胜利、中断、退出，不混成一个失真的胜率。
- [ ] 根据保存的对局队伍快照展示历史，不用当前昵称/队伍关系覆写原始结果语义。
- [ ] 实现分页、空状态、失败重试和稳定排序；统计可从源记录核对或重建。
- [ ] 两端接入一致的个人中心与历史页面，明确哪些偏好跨端同步。
- [ ] 按已确认策略处理用户内容举报、账号禁用和数据保存/删除的最小入口或运维流程。
- [ ] 保护资料与历史的对象级权限，不通过任意 userId 读取非公开记录。

## 交付与范围

涉及 identity-service 的资料、game-service 的历史、迁移、两端个人中心；优先复用 stage7/stage12 的结算源，不另造一套前端上报结果系统。

## 验收标准

- [ ] Web 修改的可同步偏好可由 App 正确读取，退出登录不会混入其他账号。
- [ ] 经典/2v2/中断场景的历史和统计与实际结算一致。
- [ ] 重复结算、服务重试不会增加多条相同战绩；分页不漏不重复。
- [ ] 无权用户不能读取或修改他人的私有资料/历史。
- [ ] 禁用/举报与数据处理流程有可执行说明，不把未实现的后台按钮当作运营能力。

## 本阶段不包含

全球排行榜、排位赛季、复杂成就、付费头像、商城和完整运营后台。

## 完成记录

待补结果类型与统计口径、数据权限测试、跨端偏好和历史一致性验证。
