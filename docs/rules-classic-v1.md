# 经典 UNO 规则模块 v1

日期：2026-09-23。实现位置：`backend/game-core/src/main/java/com/example/uno/core/rules`。

本模块以 [Mattel 经典 108 张牌说明书](https://service.mattel.com/instruction_sheets/W2085.pdf) 为基线。产品暂定每桌 2–6 位真人；官方说明书为 2–10 人。下述未由说明书明确规定的边界选择单独标出，后续产品确认若有变更须提高规则版本。

## 牌与回合

- 使用 108 张具有唯一物理 ID 的牌：四色各 25 张、万能牌 4 张、万能加四 4 张。每人发 7 张；每轮由传入的庄家席位决定首位玩家，顺时针起步。调用方须决定庄家，规则模块不接受客户端指定胜者或洗牌结果。
- 同颜色、同数字或同功能符号可出；万能牌可随时出并一次性选色。玩家即使有牌可出也可摸一张；若摸到可出的牌，只能打刚摸到的这张或放弃，不能改打原手牌。摸到不可出的牌自动结束本回合。
- 跳过让下一位失去回合；反转改变方向，两人局反转还让出牌者再行动；加二令下一位摸两张且失去回合。默认不允许叠加罚牌、抢出或 7–0 等家规。
- 开始牌为跳过、反转、加二时立即应用效果；万能牌由庄家左侧玩家先选色；万能加四放回抽牌堆重洗，重新翻开一张。

## 加四质疑、UNO 与结束

- 万能加四可被提交，即使出牌者手中仍有上一有效颜色的牌；引擎保存出牌时的有效颜色和剩余手牌作为质疑证据。只有受罚玩家可接受或质疑。接受：摸四张并跳过；质疑成功：违规出牌者摸四张，质疑者继续行动；质疑失败：质疑者摸六张并跳过。相同数字或功能符号、但颜色不同的手牌不构成加四违规。证据仅返回给质疑者。
- 打出倒数第二张牌时可同步喊 UNO，也可在下一位玩家开始动作前补喊；未喊且被其他玩家在此窗口抓到，摸两张。此处“下一位开始动作”定义为其第一次有效出牌、摸牌或加四回应；服务端计时属于 stage7，规则模块本身不读取时钟。
- 最后一张若为加二，先结算罚牌再计分；若为万能加四，先等待接受或质疑，再决定本轮是否结束。其他牌出完即结束本轮。每张剩余数字牌按面值计分，功能牌 20 分、万能牌 50 分；累计达到 500 分结束整场，否则换庄重洗开启下一轮。
- 抽牌堆耗尽时，将弃牌堆除顶牌外重洗为抽牌堆。若顶牌外已无可抽牌，普通摸牌以 `DRAW_UNAVAILABLE` 事件跳过当前玩家，避免对局死锁；罚牌按剩余可抽数量执行。这是极端资源耗尽时的产品回退规则，说明书未进一步定义，待试玩确认。

## 接口与边界

`ClassicUno.start(players,dealerSeat,random)` 建立回合；`apply(state,command,random)` 返回全新状态、事件和按席位的抽牌数量；`nextRound` 在本轮结束且尚未达到 500 分时重开；`view(state,viewer)` 只给本人完整手牌、其他玩家牌数及公共状态。`RULES_VERSION=1`。相同状态、随机输入与动作序列可重放；生产默认使用 `SecureRandom`，测试传入固定种子。

`UnoState` 是仅供服务器保存的完整状态，含所有手牌与抽牌顺序，不能直接广播。`UnoSnapshot` 仅用于服务器持久化和恢复，也不能作为玩家响应。`UnoTransition.privateReveals` 只以质疑者用户 ID 为键；实时层必须逐人发送。规则拒绝抛出带代码的 `UnoRuleViolation`，原状态不会被修改。命令去重、期望版本检查、鉴权、连接接管、30 秒回合计时和 8 秒质疑计时由 stage7/12 实现。

## 已覆盖用例

牌组成与得分；固定种子发牌和初始牌效果；合法/非法出牌；摸后出牌/放弃；两人及多人方向；加二与禁止叠加；加四合法性、质疑、接受、末张结算和定向证据；加四回应期间抓漏喊；UNO 宣告/抓漏喊窗口；弃牌堆重洗、完全无牌可抽及 108 张牌守恒；一局自动完整走到结算、累计得分与 500 分结束。
