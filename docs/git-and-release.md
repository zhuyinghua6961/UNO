## 为什么不能直接把目录当分支

普通 Git 分支描述整个仓库的快照，不是单个文件夹的版本。建议同一 monorepo 快照始终保留 backend/web/flutter/deploy，这样一次跨端协议修改可以对应同一版本。

功能分支保留完整目录结构；一次跨端协议变更在同一分支组合验证。需要隔离检出时使用同一仓库的 worktree，不在三个业务目录内另行 `git init`。

## 获取信息后的操作顺序

检查远程历史与 `master` → 确认项目路径和已有代码 → 按任务创建功能分支 → 本地验证并按授权推送。默认不强推、不覆盖历史。

## 发布约定

release 目录存实际产物，默认忽略二进制；发布清单记录版本、构建时间、源码提交（若存在）、脏工作区标记和校验和。没有提交时源码版本为 null，不伪造 Git 关联。

现有 [CI 验证工作流](../.github/workflows/ci.yml) 对所有分支的 push/PR 做 Web、后端与 Android 检查，iOS 模拟器构建仅手动触发。它尚未在远程 Runner 执行；一次可安装版本仍须追溯到明确的源码提交和跨端兼容组合。
