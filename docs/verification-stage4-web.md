# stage4：Web账号增量验收

日期：2026-09-07。范围为Web账号闭环；Flutter仍是占位入口，stage4保持部分完成。邮箱渠道仍为默认关闭的本地开发方案，不表示已获公开注册或生产部署批准。

## 已实现

- 注册、验证邮箱、重新申请验证邮件、登录、找回/重置密码、退出。
- 账号页展示后端真实昵称/邮箱/ID；可向game核对同一身份，不伪装成已能对战。
- 启动、受保护路由、重新聚焦、可见时每60秒恢复会话；失效提示重新登录，网络不明隐藏无法确认的资料并允许重试。
- HttpOnly Cookie，不把凭证写入localStorage/sessionStorage；每次写请求重新获取CSRF；密码与邮件凭证提交后清空，不放入URL。
- 提交中禁用表单，阻止重复请求，不自动重试写操作；失败不模拟成功，退出超时明确保留未确认状态。
- 恢复请求版本隔离，旧请求不能覆盖新登录/退出；登录返回目标仅允许 `/`、`/account`、`/preview`。

## 实际浏览器联调

使用本机Playwright 1.62.1的无头Chromium，不拦截或模拟账号API响应。链路：浏览器 → Vite 5179 → Gateway 29080 → identity 29081 / game 29082 → PostgreSQL 25432；邮件通过本地Mailpit SMTP 21025、收件箱28025。所有服务仅回环监听，后端从独立JAR副本运行。

已实际操作并断言：

1. 未登录打开 `/account`，跳转登录并保留站内返回目标。
2. 用随机测试邮箱注册，真实SMTP接收验证邮件，复制凭证验证成功。
3. 错误密码不进入账号页；正确密码登录，核对游戏服务为同一userId。
4. 刷新网页后恢复同一账号；浏览器Web Storage无凭证，session Cookie为HttpOnly/SameSite Strict且不可经document.cookie读取（本地HTTP例外无Secure）。
5. 第二标签页恢复相同会话；退出后identity/me与game/session均401，另一标签页刷新后回到登录。
6. 找回密码→真实邮件重置；旧密码失败、新密码成功，账号ID保持一致。
7. 模拟浏览器离线并重新聚焦后隐藏资料；恢复网络、点击重试后恢复身份。
8. 最终退出；390px窄屏与1440px桌面截图检查，窄屏无水平溢出；整段流程无页面JavaScript异常。

临时浏览器脚本与截图保存在本机临时目录，不是仓库CI测试；可按上述步骤复核。数据库仅删除本次随机测试账号及对应发件箱行，未清空共享库；本地收件箱可能保留已消费且失效的测试邮件。未记录密码/令牌或提供演示账号。
